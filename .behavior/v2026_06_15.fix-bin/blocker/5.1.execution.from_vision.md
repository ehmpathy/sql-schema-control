### blocker details

**mech-failhides (1 blocker)**:
- `execBinRunWithError` catch block catches all errors and returns result object
- rule says this "hides real errors" — but in CLI subprocess testing, non-zero exit IS the expected outcome
- the catch is intentional and documented

**arch-opport-decomposition (3 blockers, 2 nitpicks)**:
1. `execBinRun` mixes compute (`binPath + args.join`) with i/o (`execSync`)
2. `execBinRunWithError` same issue
3. `writeConnectionConfig` mixes filename/content logic with `writeFileSync`
- wants extracting: `asBinRunCommand`, `asConnectionConfigFilename`, `asConnectionConfigContent`
- this is decomposition overhead for a 5-test acceptance suite

**ergo-friction-hazards (2 blockers)**:
1. only `plan` command tested, not `apply`
2. missing error paths: plan --help, apply --help, invalid control.yml content, connection failures
- scope expansion: would need apply tests with database mocking or integration
