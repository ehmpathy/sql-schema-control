# blocker.1: Try/catch hides real errors from execSync

**rule**: .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/pitofsuccess.errors/rule.forbid.failhide.md.pt1.md

**locations**:
- src/contract/cli.acceptance.test.ts:36

The execBinRunWithError helper uses a bare try/catch around execSync without any allowlist of specific errors. It catches (error: unknown), casts it, extracts fields with defaults, and always returns a result object - never rethrowing the original error. This is exactly the failhide pattern the rule forbids: real errors (e.g. unexpected exec failures, permission issues, or non-standard error objects) are silently turned into {exitCode:1} results instead of propagating. The rule states try/catch is only permitted when it has a narrow allowlist, carefully handles only those cases, and rethrows everything else. This is a mega blocker because it can hide defects during test execution.

**snippet**:
```ts
  try {
    const stdout = execSync(
      `${input.binPath} ${input.args.join(' ')}`,
      options,
    );
    return { stdout, stderr: '', exitCode: 0 };
  } catch (error: unknown) {
    const execError = error as {
      stdout?: string;
      stderr?: string;
      status?: number;
    };
    return {
      stdout: execError.stdout ?? '',
      stderr: execError.stderr ?? '',
      exitCode: execError.status ?? 1,
    };
  }
```
