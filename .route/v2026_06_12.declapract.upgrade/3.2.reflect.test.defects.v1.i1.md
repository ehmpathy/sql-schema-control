## defect 2: snapshot path mismatch

### rationale

the upgrade renamed `src/logic/` to `src/domain.operations/`. snapshots captured the old path. this is expected behavior:

- the path rename is part of the practice upgrade
- snapshots must be regenerated after path renames
- `--resnap` flag exists for this purpose

### action

## defect 3: flaky integration tests

### classification: practice bug

### rationale

the flakiness came from `maxWorkers: '50%'` in jest.integration.config.ts. this caused race conditions when parallel tests share database state.

- the practice prescribes `maxWorkers: '50%'` for integration tests
- integration tests that share database state cannot run in parallel
- this is a design flaw in the practice, not repo-specific

### action

fixed locally: changed `maxWorkers: '50%'` to `maxWorkers: 1` in jest.integration.config.ts to run tests in series.

### recommendation

update `src/practices/tests/best-practice/jest.integration.config.ts` in declapract-typescript-ehmpathy to use `maxWorkers: 1` for integration tests. unit tests can remain parallel since they don't share state.

## defect 5: dpdm detects internal cycles in consumed packages

### classification: practice bug (minor)

### rationale

the upgrade added `test:lint:cycles` with `--transform` flag and `.dpdmrc.yaml` with empty exclude list.

with `--transform`, dpdm erases type imports before analysis and excludes test files. this handles most devDependency cycles. however, production dependencies with internal cycles (e.g., pg ↔ pg-pool within the pg package) still cause failures.

- declapract practice `.dpdmrc.yaml` has `exclude: []`
- practice guidance says "never exclude prod dependencies — you'd ship cycles to consumers"
- but internal cycles within a package (pg ↔ pg-pool) are outside our control
- the cycle is in pg's code, not in how we use pg

### action

fixed locally: added `pg` (not `node_modules`) to exclude list in `.dpdmrc.yaml`, with a comment that points to `.dream/2026_06_14.dual-publish-esm-cjs.dream.md`.

the dream file documents the plan to migrate from pg to the cycle-free `postgres` package via dual ESM+CJS.

### recommendation

update declapract practice `.dpdmrc.yaml` guidance to clarify:
- internal cycles within consumed packages can be excluded with a comment
- the exclusion should name the specific package (e.g., `pg`), not blanket `node_modules`
- a `.dream/` file should track the plan to eliminate the dependency
