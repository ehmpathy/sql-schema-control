dream = dual-publish esm+cjs to use esm-only deps (e.g., postgres instead of pg)

## .why

- pg has internal cycle (pg <-> pg-pool) that dpdm detects
- postgres (porsager/postgres) is esm-only, no cycles, modern api
- need dual-publish to support both cjs and esm consumers

## .how

1. write esm source (set `"type": "module"` in package.json)
2. tsc compiles to `dist/esm/`
3. esbuild bundles to `dist/cjs/` with esm-only deps inlined

```json
{
  "type": "module",
  "exports": {
    ".": {
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.js"
    }
  }
}
```

```js
// esbuild for cjs build
esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  format: 'cjs',
  outdir: 'dist/cjs',
  external: ['mysql2'],  // cjs-compatible deps stay external
  // 'postgres' NOT in external -> gets bundled into cjs output
});
```

## .tradeoffs

| pro | con |
|-----|-----|
| eliminates pg cycle | migration effort |
| use modern esm-only packages | larger cjs bundle (deps inlined) |
| future-proof | dual package hazard (rare edge cases) |

## .scope

- update tsconfig for esm output
- add esbuild for cjs bundle
- update package.json exports
- migrate pg -> postgres
- test both cjs and esm consumption
